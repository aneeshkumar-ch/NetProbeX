Architectural Design Guarantees

  • Zero Event Loop Starvation: All synchronous network I/O (`socket.connect_ex`, `recv`, and HTTP calls) runs in `IO_EXECUTOR`, preserving 60 FPS dashboard streaming.
  • Dual-Stack Interface Binding: Server binds to `0.0.0.0:8765`, enabling dual-stack routing across loopback (`127.0.0.1`), IPv6 localhost (`::1`), and LAN adapters.
  • Active Process Table Correlation: Concurrently maps open sockets to Windows Kernel PIDs and task names via `netstat -ano` and `tasklist /fo csv`.
  • Bounded Concurrency: Strict cap of 30 worker threads avoids OS thread thrashing and socket descriptor leaks.

Three-Stage Probe Verification Logic

STAGE 1: Non-Blocking Socket Connect Check
  socket.connect_ex((host, port)) with 200ms timeout
  │
  ├── [Return != 0] ──> Port CLOSED (Dropped silently)
  └── [Return == 0] ──> Port OPEN (Pass to Stage 2)
              │
STAGE 2: Protocol-Specific Banner Acquisition
  Execute surgical probe (HTTP HEAD, PG SSL, etc.)
  │
  ├── [No response] ──> Mark "Generic Service" (No CVE guess)
  └── [Banner recv] ──> Pass to Stage 3
              │
STAGE 3: Semver Extraction & Strict NIST Ingestion
  Regex matches exact version string
  │
  ├── [No version]  ──> Label "Unknown" (Neutral Gray Badge)
  └── [Version OK]  ──> In-Memory NVD Query & CVSS v3.1 Score

Executive Defense

Executive Q&A & Stakeholder Defense Guide

Anticipated Inquiries and Empirical Technical Defenses

12 / 12

Question from SecOps

"How do we handle packet loss over noisy WAN links?"

Technical Defense: Each port check is governed by an explicit 200ms socket timeout. Furthermore, ARGUS never alerts on a bare SYN response; stage 2 banner acquisition requires an established three-way handshake, eliminating false positives caused by WAN jitter or firewall reflections.

Question from Eng Manager

"What is the maintenance burden if NIST updates its CVE API schemas?"

Technical Defense: NVD ingestion is completely encapsulated within `lookup_nvd_cves_in_memory()`. We parse against NIST's stable v2.0 REST API with multi-key fallbacks (CVSS 3.1 > 3.0 > 2.0). If NIST modifies schema keys, only a single 15-line function requires adjustment.

Question from CISO

"How do we verify this won't cause unexpected downtime on production services?"

Technical Defense: Three-layer safety architecture: 1) `ScopeManager` cryptographically aborts if unapproved IPs are entered; 2) Probes use standard OS `connect_ex` calls without buffer fuzzing; 3) Protocol queries use standard RFC greetings that daemons handle natively.
